1. MISSION OVERVIEW
--------------------------------------------------------------------------------
In our pipeline, my module (LSTM) handles Temporal Intent. It tracks what the
user just watched to create a "State Representation." Your RL Agent will use
this "State" to select the best action (recommendation).

The Flow:
  User History (10 movies)
        |
        v
  My LSTM Model
        |
        v
  128-dim User State Vector
        |
        v
  Your RL Agent
        |
        v
  Final Recommendation Selection

4. HOW TO USE MY OUTPUT IN YOUR RL AGENT
--------------------------------------------------------------------------------

A. Defining the "State" (S)
----------------------------
In RL, the state S represents the environment. I have set my model to produce a
128-dimensional context vector. This vector summarizes the user's 10-movie
history.

  - Input to your Agent: A vector of shape (1, 128).


B. Using the State Extractor
------------------------------
I have provided extract_states.py to make your life easier. Here is how you
can get the state for your RL training loop:

You should define your Reward function using the ratings.csv:

  - If user rating <  4  :  Reward = +1

5. TECHNICAL CONSTRAINTS
--------------------------------------------------------------------------------
  - Sequence Length:
    My model is trained on a sequence length of 10. If a user has only watched
    3 movies, you must "pre-pad" the sequence with zeros:
      [0, 0, 0, 0, 0, 0, 0, Movie1, Movie2, Movie3]

  - Vocab Size:
    9,725  (9,724 movies + 1 padding index)

  - Indices:
    Always ensure you are converting movieId (from CSV) to movie_idx
    (from my JSON) before passing it to the model.

ADDENDUM — UPDATED SECTION 4-B: RECOMMENDED IMPLEMENTATION (v2)
================================================================================
The code block below is the updated and more explicit version of Section 4-B
above. Use this version for your actual implementation as it exposes all
hyperparameters explicitly and matches the real function signatures in

NOTE: The original Section 4-B above is kept for reference. This addendum

    from extract_states import load_trained_model, get_user_state
    import torch

    # 1. Setup Parameters
    VOCAB_SIZE = 9725
    EMBED_DIM  = 64
    HIDDEN_DIM = 128
    device     = torch.device('cpu')

    # 2. Load the model using Member 3's real loader
    model = load_trained_model(
        "models/lstm_model.pt",
        vocab_size     = VOCAB_SIZE,
        embedding_dim  = EMBED_DIM,
        hidden_dim     = HIDDEN_DIM,
        output_dim     = VOCAB_SIZE,
        device         = device
    )

    # 3. Extract the RL 'State' from a sequence
    # (The sequence must be 10 indices long)
    user_seq = [0, 0, 0, 102, 45, 12, 505, 31, 99, 10]
    user_state_vector = get_user_state(model, user_seq, device)

    print(user_state_vector.shape)  # Result: (128,)

--------------------------------------------------------------------------------
Key differences from the original 4-B:
  - All model hyperparameters (EMBED_DIM, HIDDEN_DIM, output_dim) are passed
    explicitly so there is no ambiguity about the model shape.
  - device is passed as a torch.device object, not a plain string.
  - output_dim is set to VOCAB_SIZE (9725), matching training configuration.
